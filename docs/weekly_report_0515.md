## 1. 요약 (Executive Summary)

이번 주 Pick & Go 예약부의 핵심 목표는 사용자가 선택한 **항공권과 숙소를 빠르고 안전하게 예약**하는 시스템을 통합하는 것이었습니다. 

항공사와 숙박업체라는 각기 다른 외부 시스템을 이용해야 하므로, 대기 시간이 길어지거나 "항공권만 예약되고 숙소는 매진되는" 난감한 상황을 방지하는 것이 가장 중요했습니다. 이를 해결하기 위해 최신 소프트웨어 설계 기법인 **'비동기 병렬 처리'**와 **'Saga(사가) 패턴'** 이론을 도입하여 전체 5단계의 예약 파이프라인을 성공적으로 하나로 연결하였습니다.

---

## 2. 핵심 설계 이론: 빠르고 안전한 예약을 위한 기술

비전공자도 쉽게 이해할 수 있도록, 이번 주에 적용된 두 가지 핵심 설계 이론을 비유와 함께 설명합니다.

### ① 대기 시간 절반으로 줄이기: 비동기 병렬 처리
*   **문제점**: 비행기 예약을 마치고 나서야 숙소를 예약하면 시간이 두 배로 걸립니다.
*   **적용 이론**: 두 명의 직원이 각각 항공사와 숙박업체에 동시에 전화를 걸어 예약을 진행하도록 시스템을 설계했습니다. 이를 통해 **어느 쪽이든 가장 오래 걸리는 하나의 시간**만 소요되므로, 전체 대기 시간을 획기적으로 단축할 수 있었습니다.

### ② "비행기표는 샀는데 잘 곳이 없네?" 방지: Saga(사가) 패턴
*   **문제점**: 비행기 예약은 성공했는데, 직후에 시도한 숙소 예약이 매진되어 실패했다면 사용자는 길거리에 나앉게 됩니다. 일반적인 단일 데이터베이스와 달리 외부 업체의 시스템은 우리 마음대로 통제할 수 없습니다.
*   **적용 이론 (Saga 패턴)**: 전체 예약 과정을 여러 단계로 쪼개고, **단 하나라도 실패하면 앞서 성공했던 예약들까지 모두 '취소 버튼'을 눌러 원상 복구(보상 트랜잭션)**시키는 안전 장치를 설계했습니다. 이를 통해 사용자에게 불완전한 부분 예약이 넘어가는 것을 완벽하게 차단합니다.

## 3. 주요 구현 모습 및 흐름

위의 이론을 바탕으로 실제 시스템이 작동하는 5단계 흐름을 하나로 통합했습니다.

1.  **예약 항목 분리 (분석)**: 사용자의 요청을 받아 항공사에 보낼 정보와 숙소에 보낼 정보를 깔끔하게 나눕니다.
2.  **동시 예약 시도 (실행)**: 모의 응답(Mock) 시스템을 이용해 항공사와 숙소 API에 동시에 예약을 요청합니다.
3.  **결과 취합 (감지)**: 두 곳에서 온 응답(성공/실패)을 하나로 모아 결과를 확인합니다.
4.  **실패 시 자동 원상 복구 (안전망)**: 만약 숙소가 실패했다면, 즉시 항공사 쪽에 "방금 전 예약 취소해주세요"라는 명령을 자동으로 보냅니다.
5.  **최종 응답 (안내)**: 모든 것이 완벽하게 성공했을 때만 사용자에게 최종 완료 메일과 화면을 제공합니다.

## 4. 테스트 시나리오 및 기능 검증 결과

실제 계약된 외부 서비스 없이도 완벽한 로직을 검증하기 위해, 모의 테스트 환경을 구축하여 다음과 같은 상황을 검증했습니다.

| 테스트 시나리오 (상황) | 시스템의 자동 대처 (구현 결과) | 검증 |
| :--- | :--- | :---: |
| **상황 A (모두 정상)** <br/>항공/숙소 모두 자리가 넉넉함 | 두 예약을 동시에 진행하고, 문제없이 최종 완료 처리함 | ✅ 통과 |
| **상황 B (일부 매진)** <br/>항공은 예약됐으나 숙소 방이 없음 | 숙소 실패를 감지하자마자, **이미 확정된 항공 예약을 자동으로 취소 처리**하여 고객에게 환불 처리(원상 복구)함 | ✅ 통과 |
| **상황 C (네트워크 지연)** <br/>숙소 서버의 응답이 늦어짐 | 항공 예약은 완료된 채로 대기하다가, 숙소의 최종 결과를 보고 확정하거나 취소함 | ✅ 통과 |

> **테스트 결론**: 설계한 대로 부분 예약(결제)이 발생하는 사고를 시스템이 스스로 인지하고 완벽하게 방어(원상 복구)하는 모습을 확인했습니다.

## 5. 발견된 문제점 및 다음 주 계획

전체 시스템을 성공적으로 하나로 묶었지만, 설계도와 실제 통합된 코드를 꼼꼼히 교차 검증하는 과정에서 보완해야 할 점들을 발견했습니다.

### ⚠️ 현재 개선이 필요한 사항
1. **DB 저장 장치 고장 시 대처 미흡**: 비행기와 숙소 예약을 모두 마치고 마지막으로 우리 서버(DB)에 영수증을 저장하려는 찰나에 서버가 꺼진다면? 
   * **문제점 발견**: 현재 구현에서는 에러 메시지만 띄울 뿐, 이미 바깥에서 결제된 비행기와 숙소를 취소해주지 않는 **치명적인 헛점**을 발견했습니다. (Saga 패턴의 마무리 단절)
2. **외부 서버가 무한정 멈출 때의 대처 미흡**: 비행기 예약 서버가 고장 나서 아무 응답도 주지 않을 때, 우리 시스템이 영원히 기다리는 현상(타임아웃 미구현)을 확인했습니다.
