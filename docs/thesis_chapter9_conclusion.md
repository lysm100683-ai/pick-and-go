# 제 9 장 결론 및 향후 연구

본 논문은 파편화된 여행 준비 과정을 통합하여 사용자 편의를 극대화하는 AI 기반 맞춤형 여행 일정 생성 및 원스톱 예약 자동화 시스템, **Pick & Go**의 설계 및 구현 과정을 다루었다. 특히 대용량 위치 데이터 탐색의 성능 저하 문제와 분산 환경에서의 예약 데이터 정합성 문제를 해결하기 위해 시스템의 백엔드 아키텍처를 'DB부'와 '예약부'로 세분화하여 구조적 최적화를 달성하였다.

---

## 9.1 연구 성과 요약

본 연구를 통해 도출된 핵심 기술적 성과와 기여는 다음과 같다.

**1. 대규모 위치 기반 데이터베이스(DB부) 탐색 최적화**
기존의 파일 기반 저장소와 단순 좌표 수치 비교 방식이 지닌 선형적 O(N) 성능 저하 문제를 극복하기 위해, PostgreSQL의 **PostGIS 모듈과 GiST 공간 인덱스**를 전면 도입하였다. 반경 탐색 함수를 `ST_Distance`에서 인덱스 프루닝(Pruning)이 가능한 `ST_DWithin`으로 전환함으로써, 데이터 건수 증가에도 탐색 시간이 O(log N)으로 수렴하도록 아키텍처를 개선하였다. 벤치마크 결과, 데이터 100만 건 환경에서도 0.06초 이내의 빠른 응답 속도를 보장하며 실시간 글로벌 서비스가 가능한 인프라를 입증했다. 더불어 **배치 기반 Bulk Upsert** 구조를 도입하여 장소 데이터 수집 시 발생하는 I/O 병목 현상을 95% 이상 절감하였다.

**2. Saga 패턴 기반 분산 예약 파이프라인(예약부) 무결성 확보**
Amadeus(항공)와 Booking.com(숙소) 등 다수의 외부 독립 API와 연동하며 발생하는 분산 트랜잭션의 '부분 성공(Partial Failure)' 결함을 해결하기 위해 **Saga 패턴 기반의 5단계 파이프라인(Sub 1 ~ Sub 5)**을 독자적으로 설계하였다. 
로컬 DB 트랜잭션과 비동기 외부 API 호출의 범위를 분리하고, 실패 시 역순으로 기예약을 취소하는 **보상 트랜잭션(Compensating Transaction)** 로직을 구현하여 데이터 불일치를 원천 차단했다. 나아가 UUID v4와 JSONB를 결합한 유연한 예약 상태 추적 스키마를 구성하고, 파이프라인 진입점인 Sub 1(예약 검증부)에 대한 철저한 단위 테스트를 통과시킴으로써 프로덕션 레벨의 견고성을 달성하였다.

---

## 9.2 향후 연구 및 개선 방향

Pick & Go 시스템은 현재의 아키텍처를 기반으로 충분한 상용화 가능성을 입증하였으나, 글로벌 트래픽의 대규모 확장을 대비하여 다음과 같은 추가적인 고도화 연구가 요구된다.

**1. 메시지 브로커(Message Broker) 기반 이벤트 주도 아키텍처 도입**
현재 파이프라인 모듈 간의 전파(특히 Sub 4에서 Sub 2로의 롤백 시그널)는 인메모리(In-Memory) 비동기 호출에 크게 의존하고 있다. 향후 Apache Kafka나 RabbitMQ와 같은 분산 메시지 큐를 도입하여 서브시스템 간의 결합도를 완벽히 끊어내고(Decoupling), 서버 다운타임 발생 시에도 미처리된 보상 트랜잭션을 안전하게 재시도(Retry)할 수 있는 이벤트 주도 아키텍처(EDA, Event-Driven Architecture)로의 전환이 필요하다.

**2. 실제 결제 게이트웨이(PG) 연동 및 트랜잭션 고도화**
본 연구의 예약 파이프라인은 외부 API 모의 호출(Mock) 및 가상 결제를 기준으로 검증되었다. 향후 토스페이먼츠(Toss Payments) 등 실제 결제 대행사(PG, Payment Gateway) 시스템을 연동할 경우, 사용자의 결제 승인 프로세스와 Sub 3(예약 확정 검증부)가 맞물려 더욱 복잡한 3-way 통신 장애가 발생할 수 있다. 이를 대비해 결제 대기 상태(Pending Auth)와 예약 확정을 동기화하는 추가적인 상태 머신 설계가 연구되어야 한다.

**3. 머신러닝 기반 일정 생성 모델의 캐시 적중률 향상**
이동시간 캐시 데이터베이스에 축적된 사용자 이동 패턴을 머신러닝(ML) 알고리즘으로 분석하여, 미래에 질의될 확률이 높은 A-B 구간을 백그라운드 워커를 통해 사전 적재(Pre-fetching)하는 방식이 적용된다면, 캐시 적중률(Cache Hit Ratio)을 높이고 API 호출 비용을 더욱 획기적으로 낮출 수 있을 것이다.

결론적으로, 본 논문에서 확립한 데이터베이스 탐색 최적화 및 분산 예약 처리 아키텍처는 향후 Pick & Go가 수백만 명 이상의 사용자 트래픽을 처리하는 차세대 글로벌 여행 플랫폼으로 성장하기 위한 견고한 기술적 초석이 될 것이다.
